# Inventory — API routes

> Base path `/v1`. Grouped by Postman folder (`postman/collection/<NN Folder>/`). `postman/scripts/coverage.ts` fails CI when a route here or in code has no Postman request file.
> **Context** is the coarse guard. Fine-grained CASL abilities are declared per route when it is built.
> Context values: `public`, `api_key` (lead source / API client), `any` (any signed-in context), `borrower`, `partner` (CA/DSA), `partner_owner`, `lender`, `staff`, `signed` (webhook signature).
> `planned` rows: evidence = plan §10.2 (plus §3.4 for auth and §7 for leads).
> `useful` rows: evidence = the controller named in the section header, the Postman request file of the same name, and the automated checks `pnpm inventory:check` (code ↔ this file) and `pnpm postman:coverage` (code ↔ Postman). Both pass as of 2026-10-09.

## Versioned config route pattern

Generated by `createVersionedConfigController({ resource, path, name })` (`backend/src/modules/config-publishing/http/versioned-config.controller.ts`). Each resource lists its concrete rows in its own section below so `pnpm inventory:check` and Postman coverage see every route.

| Method | Path |
|---|---|
| `GET` `POST` | `/admin/{resource}` |
| `GET` `PATCH` | `/admin/{resource}/:id` |
| `POST` | `/admin/{resource}/:id/versions` |
| `GET` `PATCH` | `/admin/{resource}/:id/versions/:number` |
| `POST` | `/admin/{resource}/:id/versions/:number/submit`, `/publish`, `/retire` |

Approval and rejection are not per resource: they go through the shared checker inbox `/admin/change-requests/:id/approve|reject`. Resource-specific extras (question-set `preview`, routing-rule `simulate`) are separate controllers on the same path prefix.
